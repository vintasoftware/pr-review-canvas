01 / SEMANTIC LAYERS

Understand the change.
One concern at a time.

A large PR can tell several stories at once. Layers give each one a place.

A new capability might touch a schema, an endpoint, a client, and a test. The canvas groups the relevant diff hunks by behavior or decision, so you can follow that capability across the codebase.

Layers aren't directories, commits, or separate PRs. Different hunks in the same file can belong to different layers. Every hunk is assigned exactly once during validation, and tests follow the code they cover.

Each layer can include rationale, trade-offs, test notes, checks to do by hand, and a diagram when it helps explain the change. You review the source and mark your progress as you go.

02 / MECHANICAL-CHANGE FOLDS

Less scrolling.
More signal.

Import-only edits, whitespace changes, moved code within a file, and ranges selected by the generator can start collapsed. A small summary holds their place.

Expand a fold whenever you need the details. Edited moves keep their changed text visible, and links into folded code reveal the target. Moves between files still appear as deletions and additions.

Folded means tucked away, never reviewed on your behalf.

FROM INSTALL TO FIRST REVIEW

Bring a PR.
Build some context.

You'll need Node.js 22+, npm, Git, and an authenticated GitHub CLI.
Use Claude Code or Codex to generate a canvas.

01

Install & set up a project

Install the CLI once. Set up the skill in each repository you want to review.

npm install -g @vintasoftware/pr-review-canvas
cd /path/to/your-project
gh auth login
pr-review install-skill
pr-review doctor

The skill is installed for both Claude Code and Codex. Restart your agent if it doesn't appear.

02

Author: generate & share

In your coding agent, run the skill with your PR number:

/pr-review-canvas 123

Open the returned local URL to check the canvas. Then drag the exported ZIP into the PR description in GitHub and save. Uploading is a manual browser step.

03

Reviewer: open & review

From your own clone of the project, start the local server:

pr-review serve

Open http://localhost:3010, enter the PR number, and leave the terminal running. The app discovers the shared canvas and gets source diffs from your clone.

+

Add optional AI Chat

Install acpx and sign in to Claude Code or Codex on the same machine.

npm install -g acpx
pr-review doctor --all-checks

Restart the server. In settings, choose your agent, optionally set a model, click Test agent, and save. Reading a canvas doesn't require chat.

After new commits

Authors rerun the skill and replace the ZIP; reviewers click refresh. An outdated canvas remains readable, but posting is disabled until you're reviewing the current head.

A FEW PRACTICAL DETAILS

Before your
first review.

Does this replace my GitHub workflow?

Your PR and feedback still live on GitHub. The canvas is another way to read the changes and post comments or reviews. Teammates can keep reviewing directly in GitHub.

What's inside the shared ZIP?

PR description, file and hunk metadata, and generated review notes. Source diffs come from each reviewer's clone, and chat history stays local. Check the archive before sharing because its metadata and notes may contain private information.

Can I review without AI Chat?

Yes. The author uses a coding agent to generate the canvas, but a reviewer can read the shared canvas and diffs without installing acpx or enabling chat.

How does review completion work?

Track progress as you inspect each layer. Approval requires every layer except Other changes to be reviewed for the current head. Requesting changes doesn't require completion. Preview and edit the review body before posting.

How much does it cost?

PR Review Canvas is free, Apache-2.0 open-source software. Reuse your existing Claude Code or Codex subscription for generation and chat. Provider usage limits and charges still apply; there's no separate Canvas subscription.

Where can I find the complete documentation?

See the README for setup and the CLI and configuration reference for commands, settings, and troubleshooting.
