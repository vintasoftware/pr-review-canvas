Whylandmark 3 of 5

Keys come from the anchor, not the title

A decision's key is a hash of its file and the code around it, so renaming the decision keeps the reader's pick.

When the tour is generated again, every decision gets a fresh title. If the key came from the title, a reworded decision would look new, and the reader's earlier keep or change would be lost. So decisionKey() hashes the anchor path and the three lines around it.

This means a decision moves with its code. Move the function to another file and the key changes on purpose: the reader should look again, because the code they judged is gone.

one decision waits here

The title is gone from the key. What the reader judged was the code, so the key is the code: the anchor's path and the lines around it.
